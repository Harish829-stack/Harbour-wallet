# Harbour Wallet security findings (audit of 2026-11-16)

Branch `security/audit-2026-11-16` (from `codebase-structuring` at `c01e037`). Paths are relative to the repository root; `EXT` = `harbour-wallet-v3/apps/extension`, `BE` = `harbour-wallet-v3/apps/backend`. Plain-language explanations with the same numbers are in `SECURITY_EXPLAINED.md`.

**What was verified:** extension unit tests 596/596 (587 before, 9 added), `tsc --noEmit`, ESLint with zero warnings, the npm audit gate, and a production `vite build` (in this session). On the owner's Mac (2026-11-16, run by the owner, output pasted back): the full Docker Compose stack built and started with every service healthy, `./run.sh smoke` passed, and `go test -race ./...` passed in every backend package except `TestRequireTLSHBA`, a macOS-only failure fixed in `5e58bdf` (row 20). **What was not:** `govulncheck` and `gosec` were not run, the GitHub Actions workflows were not executed, the Railway images were not built, and nothing was tried in a real browser, on real biometric hardware or on a Ledger. Rows that depend on those say so.

## Areas reviewed with no new finding

Extension: manifest and CSP (no remote code, no `web_accessible_resources`, Trusted Types), content script and injected provider bridge, internal message router and sender checks, provider request router and approval queue, typed-data / calldata decoding, phishing lists, remote config signature, notifications and link handling, logger redaction, clipboard handling, QR sync limits, device-key client for the backend. Backend (read, not compiled): device authentication and replay protection, idempotency, rate limits, third-party gateway allow-lists, media proxy (SSRF guards), webhook signature check, realtime tokens, push endpoint allow-list, upstream key scrubbing in errors, NATS per-service permissions, Docker and Compose files.
